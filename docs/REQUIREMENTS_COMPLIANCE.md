# ClawGuard V1.0 需求符合性说明 (Requirements Compliance)

本文档对照《ClawGuard 核心功能需求》逐条说明当前实现的符合情况与差距。

---

## 1. 指令安全拦截层 (Instruction Interception Layer)

| 需求项           | 状态    | 说明                                                                                                                                             |
| ---------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **黑名单过滤**   | ✅ 符合 | `core/danger.py` 实时扫描 Shell 指令，拦截 `rm -rf`、`mkfs`、`dd`、`chmod 777`、`sudo rm/dd/mkfs`、`curl/wget \| sh`、重启/关机等。              |
| **正则匹配**     | ✅ 符合 | 全部使用正则表达式匹配，降低简单字符串拼接绕过（如 `r'm' -rf` 仍可能绕过，复杂混淆需后续增强）。                                                 |
| **敏感文件保护** | ✅ 符合 | 禁止访问系统关键路径：`/etc/`、`/boot/`、`~/.ssh`、`.ssh/`、`System32`、`/root/`、`/usr/bin/`、`/usr/sbin/` 等（见 `SENSITIVE_PATH_PATTERNS`）。 |

---

## 2. 人在回路审批流 (Human-in-the-Loop Approval)

| 需求项           | 状态    | 说明                                                                                                                                                                                                                  |
| ---------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **操作分级**     | ✅ 符合 | 只读（自动通过）：`ls`、`cat`、`pwd`、`echo`、`whoami`、`date`、`grep`、`find` 等无写操作；写操作（需确认）：含 `>`、`>>`、`tee`、`cp`、`mv`、`mkdir`、`touch` 等；危险操作（严格拦截）：由黑名单与敏感路径规则处理。 |
| **即时通讯推送** | ✅ 符合 | 通过 Telegram Bot 或 WeChat Webhook 向用户推送审批请求（`core/approval.py`）。                                                                                                                                        |
| **一键决策**     | ✅ 符合 | 推送内容包含一键链接：点击「Approve」链接即通过、点击「Deny」链接即拒绝；也可使用 HTTP API `/clawguard/approve?id=...`、`/clawguard/reject?id=...`。                                                                  |

---

## 3. 资源与成本监控 (Resource & Cost Monitor)

| 需求项           | 状态        | 说明                                                                                                                                                                            |
| ---------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Token 熔断**   | ✅ 符合     | 支持单次任务/时间窗口内最高 Token 消耗（`core/tokens.py`）。可通过 `CLAWGUARD_TOKEN_LIMIT`、`CLAWGUARD_TOKEN_WINDOW_SEC` 配置；设置 `TOKEN_WINDOW_SEC=86400` 即为「每日」额度。 |
| **执行耗时统计** | ⚠️ 部分符合 | 已提供配置项 `CLAWGUARD_MAX_EXECUTION_SEC`（占位）；实际「监控脚本运行时间、防止长时间占用」需由下游执行器（OpenClaw 或 Shell 执行环境）配合实现，代理层不直接执行命令。        |

---

## 4. 运行环境沙箱化 (Environment Sandboxing)

| 需求项           | 状态    | 说明                                                                                                                                                                        |
| ---------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Docker 隔离**  | ✅ 符合 | 提供一键配置示例：`docker-compose.example.yml`，可将 ClawGuard 及 `/workspace` 卷置于 Docker 中运行；OpenClaw 可部署于宿主机或另一容器，通过 `CLAWGUARD_TARGET_HOST` 指定。 |
| **文件系统映射** | ✅ 符合 | 仅允许 AI 读写指定目录：默认 `/workspace`，可通过 `CLAWGUARD_SANDBOX` 配置；路径重写逻辑在 `core/sandbox.py`，将绝对路径重定向到沙箱目录。                                  |

---

## 总结

- **已完全覆盖**：指令安全拦截（黑名单 + 正则 + 敏感路径）、人在回路（操作分级 + Telegram/WeChat 推送 + 一键 Approve/Deny）、Token 熔断（含每日额度配置）、沙箱（默认 `/workspace` + Docker 示例）。
- **部分覆盖**：执行耗时——仅提供配置占位与说明，实际限时需执行端配合。
- **可选增强**：更复杂的命令混淆检测、Telegram Bot 解析 `/approve`/`/deny` 文本指令、流式响应中的 Shell 拦截等，可按后续版本迭代。
